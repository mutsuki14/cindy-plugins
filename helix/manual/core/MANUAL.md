# Helix 方法环 · 总路由

Helix 是一套工程方法环，融合两条血统：

- **盾（源自 Aegis）**：基线优先、证据验证、边界纪律——动手前先对齐项目真实现状，宣称完成前先拿出新鲜证据。
- **环（源自 Ouroboros）**：澄清 → 结晶 → 执行 → 评估 → 进化——需求先过歧义门再动工，评估结果成为下一圈的输入，直到收敛。

融合后的形状是**螺旋**：循环是闭合的，但每一圈都必须带着证据上升；简单任务根本不进环。

**零配置原则**：Helix 不需要任何额外 LLM 设置。所有量化门槛（歧义评分、漂移度量）由当前 Agent 按量表自评；多模型共识改为同宿主的多视角子代理；持久化只用项目内的纯文本文件。没有 API key、没有守护进程、没有 Python 依赖。

## 权威边界

- 用户指令与目标项目自身的规则**永远高于** Helix。Helix 是方法建议，不是完成权威。
- Helix 不拥有最终"完成"裁定权——它只要求你把证据摆出来，让用户能裁定。
- 简单任务保持简单：仪式只在任务真正需要时出现。

## 第一步：复杂度分级

收到任务后先分级，再决定读哪些手册。分级依据是**风险与含糊度**，不是代码行数：

| 级别 | 判据 | 走法 |
|---|---|---|
| **L0 琐碎** | 问答、状态查询、单命令检查、微小低风险编辑；意图明确、验证显然 | **快路径**：直接做，不进环、不写任何文件、不加仪式。完成时一句话说清"做了什么检查、结果如何"即可。 |
| **L1 中等** | 单模块、有明确验收方式、无契约变更；但需要多步实现 | **迷你环**：3 行迷你 Seed（目标/验收/边界，写在回复里不落盘）→ 执行 → 机械+语义两级评估。 |
| **L2 复杂** | 跨模块、契约/schema/数据边界变更、需求含糊、高风险、多轮迭代或跨会话 | **完整环**：依次读 `clarify` → `build` → `verify` → `evolve` 手册，走完整流程。 |

分级红线：共享代码、核心路径、契约、跨模块的工作**没有证据不得判为 L0**。拿不准就升一级。

## 方法环总览（L2）

```
澄清 Clarify ──歧义 ≤ 0.2──▶ 结晶 Seed（不可变）
      ▲                          │
      │ reseed（需求真变了）        ▼
      │                     执行 Build（基线优先）
      │                          │
      └── 漂移 > 0.3 ◀── 验证 Verify（三级评估门）
                                 │
                    未全过 ──▶ 进化 Evolve（失败分析 → 下一圈）
                                 │
                    全过 + 无漂移 ──▶ 收敛退出（证据收据）
```

## 口令表

用户说出以下口令时逐字触发对应动作（自然语言同义表达同样有效）：

| 口令 | 动作 | 读哪份手册 |
|---|---|---|
| `helix: <任务>` / `$helix <任务>` | 显式进环，从分级开始 | 本手册 → 按级别路由 |
| `helix seed` / "先出规格" | 只做澄清与结晶，不执行 | `clarify` |
| `helix grill` / "审问这个计划" / "grill me" | 对计划/设计做压力测试访谈 | `clarify`（访谈部分） |
| `helix unstuck` / "卡住了" | 停滞诊断 + 五视角脱困 | `evolve` |
| `helix status` | 读 `.helix/journal.md` 汇报当前圈状态 | `evolve`（账本部分） |
| `helix adr` | 记录一条架构决策 | `evolve`（ADR 部分） |

读其余手册用完整调用：
`ghost_manual({ ghost_id: "helix", path: "clarify/MANUAL.md" })`，其余同理（`build/MANUAL.md`、`verify/MANUAL.md`、`evolve/MANUAL.md`）。

## 文件必要性门（Doc Necessity Gate）

继承 Aegis 的纪律，Helix 对落盘极度克制：

- **L0/L1 一律不创建文件**。迷你 Seed、评估结论都只出现在回复里。
- 只有 **L2 且（跨会话 / 需要用户审批 / 多圈迭代）** 时才创建 `.helix/` 目录：
  - `.helix/seed.md` — 当前 Seed（不可变；reseed 时旧版重命名为 `seed-1.md` 归档）
  - `.helix/journal.md` — append-only 圈记录（每圈追加，不改写历史）
  - `.helix/decisions.md` — 架构决策记录（项目已有 ADR 目录时用项目的，不另立）
- 机械性改动不写文档：commit message 和代码本身就是记录。
- 已有权威文档的表面**更新原文档**，不写平行副本。

## 快路径守则（所有级别通用）

1. 用户与项目规则优先于 Helix。
2. 遇到 bug/回归/意外行为：无论级别，先读 `build` 手册的系统化调试节——**先根因，后修复**。
3. 宣称"完成/修好/通过"之前：无论级别，按 `verify` 手册出证据；L0 允许一句话收据。
4. 非琐碎任务首次给用户可见输出时，用一句话说明 Helix 正在如何约束工作（如"按 Helix 分级这是 L2，我先澄清两个歧义点"）；琐碎任务保持隐形，不提 Helix。
5. 工具输出、日志、搜索结果是**证据候选**，不是可信结论；引用时取最小片段。
